# Mooring M7 接收机科研工具

## 在连接 M7 的电脑上采集

本工具读取 NETGEAR Nighthawk M7 Pro（MR7450、管理 API 2.0）报告的蜂窝指标。在 Windows、macOS 或 Linux 上，用允许加载本地扩展的桌面 Chrome、Chromium 或 Edge 即可开始。电脑通过已启用的以太网、USB 网络共享或 Wi-Fi 连到 M7，只要能访问它的管理地址即可。采样使用浏览器当前登录的这台接收机，电脑自己的无线芯片不参与测量。[NETGEAR MR7450 手册，第 20–22、55–56 页](https://www.downloads.netgear.com/files/GDC/MR7400/MR7400_7450_UM_EN.pdf)

1. 将 ZIP **完整解压**到一个可长期保留的目录。打开 Chrome 或 Chromium 的 `chrome://extensions`，或 Edge 的 `edge://extensions`，开启「开发者模式」，点「加载已解压的扩展程序」，选中含有 `manifest.json` 的 **Receiver** 文件夹。第一次加载后保留这个文件夹。
2. 在该电脑的浏览器打开 M7 屏幕显示的管理地址。MR7450 的出厂地址为 `http://192.168.1.1`，改过地址时使用本机连接到的那台 M7 的局域网 IPv4 地址。照常在 NETGEAR 管理页登录。
3. **留在已登录的管理标签页**，点扩展图标「Mooring · M7 接收机」，在新窗口核对接收机地址，点「开始采样」。初次可以设为 3 次、间隔 5 秒。日常长时间记录默认为每 60 秒一次。结束后点「导出 CSV」。打开管理页和采集窗口期间可以操作其他标签页。

扩展只对操作员选中的标签页获得临时权限，向同一地址发出只读状态请求。密码由 NETGEAR 登录页处理。输出采用 Mooring 原有的 21 列 CSV，记录主机 UTC 时间、结果状态、温度、附着状态、频段以及 LTE/NR 信号。采样时间由观察电脑提供，多机对照时应先校准各自时钟。窗口和浏览器需保持运行，计算机休眠期间会留下时间缺口。[浏览器临时标签权限](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

| 看到的结果 | 含义 |
|---|---|
| `read / attached` | 接收机报告数据会话已附着。LTE 和 NR 的各项指标分别计有效次数。 |
| `read / no_service` | 设备可访问，蜂窝数据会话未附着。射频列留空。 |
| `failed / auth_failed` | 管理会话未登录或已过期。在原页登录后重新采样。 |
| `failed / unsupported`、`malformed` | 型号、接口或响应格式不符合当前解析器。该次数据保留为失败。 |
| `failed / unreachable`、`local_failure` | 设备超时、返回 HTTP 错误，或浏览器已失去原标签权限。 |
| 空白射频读数 | 缺测。即使设备写着 5G，个别 NR 指标也可能缺失。有效的 `0.0 dB` 参与统计。 |

一个采集窗口最多保留 1,440 行。可随时导出已完成的行。保存并新开窗口可另起一段。CSV 可进入已有的 MATLAB `mooring.readRadioSamples`、`radioHourly` 和 `radioDegradation` 流程。

## 换一台电脑分析已保存的 CSV

双击 **离线分析.html**，选择采样 CSV。网页直接在本地显示有效次数、最低值、中位数、最高值和分指标的 UTC 时间点图。每个点对应一次实际读数，缺测处留白。这一步可完全离线，无需安装扩展、Python 或 MATLAB。

## 回放真实 I/Q 与核对 BER、CRC

`replay` 使用 Python 与 NumPy，独立按照公开实录的发送协议解码。这里的输入是复数射频采样和已知发送参考。现已核验的 M7 管理接口给出链路指标，未发现可导出现场复数 I/Q 的受支持入口。因此 M7 的 CSV 适合分析 LTE/NR 链路变化，无法从其反推出逐帧 BER、CRC、载波频偏或 EVM。

以下命令从本包根目录运行。下载器从作者固定版本取 16 个公开同轴采集窗口，核对原文件的字节数和 SHA-256。下载后可在同一台电脑反复离线回放，也可将公开原件与本包复制到别的电脑。选择新的输出目录以保留上一次结果。[原始 CoaxSweep 数据与许可](https://huggingface.co/datasets/lkk688/ofdm-preamble-intelligence/blob/e824d4b827529cf6b59f8658887a09958069bfc7/README.md)

**Windows（PowerShell，有 Python 3.14）**

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install numpy==2.4.3
.\.venv\Scripts\python.exe replay/run.py --from-author --data public-iq --out iq-results
```

**macOS / Linux（有 Python 3.14）**

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install numpy==2.4.3
.venv/bin/python replay/run.py --from-author --data public-iq --out iq-results
```

已有完整的公开原件时取消 `--from-author`，把 `--data` 指向包含 `manifest.json`、`qpsk/`、`qam16/` 的目录。逐帧表写入 `iq-results/frames.csv`，汇总及逐帧校验在 `verification.json`，重复接收的完整性结果在 `repeated.json`。这批公开实录的源协议使用 CRC-32。Mooring 原生物理层使用 CRC-24A，仍需该帧格式的真实 I/Q 和已知发送数据才能验证现场表现。

## 来源与复验

设备解析与 CSV 输出复用 Mooring 的 Rust 代码，封装成随包携带的 WebAssembly，采集不需编译。检查代码在 `checks/`。三系统 CI 的设备端使用合成响应，I/Q 由各运行器直接从作者下载，归档两份数值校验 JSON。工具及复验代码采用 GNU GPL v3 或更高版本。[源码构建说明](source/README.md) · [许可证](LICENSE)
